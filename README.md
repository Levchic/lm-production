# Портфолио-сайт — инструкция

Сайт статический (HTML/CSS/JS, без сборки и зависимостей). К нему прилагается
локальная админка на Node — через неё редактируется весь контент и загружаются
фото, видео и аудио.

---

## 1. Как запустить

Двойной клик по **`start.command`** в папке проекта. Откроется админка, а сайт
станет доступен по адресу `http://localhost:4000/`.

То же самое из терминала:

```bash
npm start
```

Остановить — `Ctrl+C` в окне терминала.

**Пароль в админку** по умолчанию `admin`. Поменяйте его в `start.command`,
строка `ADMIN_PASSWORD="admin"`.

### Зайти в админку с телефона

Сервер слушает всю локальную сеть (`BIND_HOST=0.0.0.0` в `start.command`),
поэтому при запуске он печатает адрес для телефона:

```
  С ТЕЛЕФОНА — той же сети Wi-Fi:
      http://192.168.1.5:4000/admin.html
```

Наберите **именно этот адрес** в браузере телефона. `localhost` не подойдёт:
для телефона `localhost` — это сам телефон, а не мак.

Что стоит знать:

- Mac должен быть включён, не спать и оставаться в той же сети. Чтобы не
  засыпал при долгой правке с открытой крышкой, запустите в соседнем окне
  `caffeinate -d`.
- **Чтобы сервер жил с закрытой крышкой**, одного `caffeinate` мало — закрытие
  крышки усыпляет мак поверх любых таких запретов. Нужно разово выполнить
  `sudo pmset -a disablesleep 1` (вернуть обратно — `sudo pmset -a disablesleep 0`)
  и держать мак в розетке. Проверить текущее состояние: `pmset -g | grep -i sleep`.
- Адрес меняется при переподключении к другой сети — смотрите тот, что
  напечатан при запуске.
- Если включён файрвол macOS, он один раз спросит, разрешить ли `node`
  принимать входящие соединения — нужно разрешить. При выключенном файрволе
  никакого вопроса не будет, это нормально.
- Адрес виден всем в этой сети. Дома это нормально, в кафе и коворкингах
  сервер лучше не оставлять запущенным — или верните `BIND_HOST="127.0.0.1"`.
- Переменная называется `BIND_HOST`, а не `HOST`, потому что `HOST` в zsh
  уже занята под имя компьютера — с ней сервер слушал бы только сам мак.
- Работает только в пределах одной сети. Чтобы заходить откуда угодно, нужен
  либо VPN вроде Tailscale, либо настоящий хостинг с Node.

Правки с телефона пишутся в `js/content.js` на маке — выкладка на хостинг
по-прежнему отдельным `git push`.

Если нужен только просмотр сайта без админки — подойдёт любой статический сервер:

```bash
python3 -m http.server 8080
```

## 2. Админка

Открывается по адресу `http://localhost:4000/admin.html` (или сама при запуске
`start.command`). Слева — разделы, справа — поля. Кнопка **«Сохранить»**
(или `⌘S`) записывает всё в `js/content.js`. После сохранения обновите вкладку
с сайтом, чтобы увидеть изменения.

### Что можно редактировать

| Раздел | Что внутри |
|---|---|
| Общее | заголовок вкладки, описание для поисковиков, логотип, пункты меню, подвал |
| Главный экран | текст первого экрана, фоновое фото, видео под ним |
| Обо мне | короткий текст (главная), полный текст (страница «Обо мне»), портрет, теги |
| Для кого | заголовки, фото в фоне раздела, карточки |
| Процесс | шаги работы |
| Портфолио | проекты: тексты, категория, цифры, этапы, фото, видео, аудио; порядок и фильтры |
| Услуги | список услуг: цена, фото в фоне карточки, подробности и список «что входит» — они раскрываются на сайте по клику |
| Отзывы | отзывы со статусами (опубликован / на модерации / скрыт) |
| Новости | записи с датой, рубрикой, анонсом и полным текстом |
| Контакты | почта, телефон, соцсети, подписи в форме |
| Медиатека | все загруженные файлы: просмотр и удаление |

### Два языка

Сверху переключатель **RU / EN**. Обычные поля правятся отдельно для каждого
языка. Поля с пометкой «общее для RU и EN» (пути к файлам, ссылки, id, цифры)
пишутся сразу в оба языка — переводить их не нужно.

Добавление, удаление и перестановка элементов списка всегда применяются
к обоим языкам сразу, поэтому русская и английская версии не разъезжаются.
Новый проект появляется в EN с русским текстом — переключитесь на EN
и переведите.

### Порядок элементов

Стрелки ↑ ↓ у каждого элемента. Порядок в админке = порядок на сайте.
На главной показываются первые 3 проекта, первые 3 услуги и первые 3 новости —
всё остальное на отдельных страницах.

### Загрузка фото, видео и аудио

Кнопка «Выбрать файл» → «Загрузить файлы». Файлы приводятся к web-формату
автоматически:

- **фото** — сжимаются до 2200px по длинной стороне и переводятся в JPEG
  (включая `.HEIC` и RAW `.DNG` с телефона и камеры);
- **видео** — перекодируются в MP4 (H.264, до 1280px по ширине), плюс
  автоматически создаётся кадр-заглушка: страница показывает его вместо
  того, чтобы грузить десятки мегабайт видео до нажатия play;
- **аудио** — переводится в MP3 192 kbps.

Исходники остаются у вас на компьютере нетронутыми — в проект попадают только
сжатые копии. Имена файлов и папок транслитерируются (`Гарри Поттер` →
`garri-potter`), потому что кириллица в адресах ведёт себя непредсказуемо.

Для видео и аудио нужен **ffmpeg**. Если его нет:

```bash
brew install ffmpeg
```

Без него фото всё равно обрабатываются (через встроенный в macOS `sips`),
а видео и аудио сохраняются как есть — админка об этом предупредит.

### Новости

У каждой новости есть обложка, галерея фото, ссылка на видео и список ссылок.
На карточке видно обложку, рубрику и, если задано видео, значок плеера; сама
статья открывается отдельной страницей `post.html?id=…`.

- **Обложка** — если не выбрать, карточка возьмёт первое фото из галереи;
  если фото нет вовсе, нарисуется «нотный» фон, и лента не будет выглядеть
  дырявой.
- **Ссылка на видео** — вставьте адрес ролика с YouTube, VK или Rutube из
  адресной строки: на странице статьи появится встроенный плеер.
- **Пустая строка в тексте** = новый абзац на странице.

### Модерация отзывов

У каждого отзыва есть статус. На сайт попадают только со статусом
**«Опубликован»**. «На модерации» и «Скрыт» видны только в админке.

На сайте, под каруселью отзывов, есть кнопка **«Оставить отзыв»**. Посетитель
заполняет имя, текст, при желании — оценку и ссылку на свой профиль VK или
Telegram, и ставит галочку согласия. Отзыв приходит в админку со статусом
**«На модерации»** — на сайте его никто не видит, пока вы не переключите статус
на «Опубликован». Форма работает только когда запущен сервер (`npm start` или
хостинг с Node); на «голой» статике она честно скажет посетителю написать
в мессенджер.

Отзывы с других площадок (Авито, VK) переносятся руками: у каждого отзыва есть
поля **«Откуда отзыв»** и **«Ссылка на первоисточник»** — на карточке появится
значок площадки и ссылка на оригинал. Автоматически подтянуть отзывы с Авито
нельзя: публичного API отзывов у них нет.

### Резервные копии

Перед каждым сохранением предыдущая версия `js/content.js` копируется
в папку `backups/` (хранятся последние 30). Если что-то испортилось —
скопируйте нужный файл оттуда обратно в `js/content.js`.

## 3. Структура сайта

```
index.html      — главная: обзор всех разделов
about.html      — «Обо мне»
services.html   — все услуги с ценами
portfolio.html  — все проекты с фильтром по категориям
project.html    — страница одного проекта, ?id=... (например project.html?id=burton-show)
blog.html       — новости
admin.html      — админка (работает только при запущенном сервере)
```

Разделы «Для кого», «Процесс», «Отзывы» и «Контакты» живут только на главной —
пункты меню ведут на якоря `index.html#process` и т.д.

### Файлы

```
css/styles.css      — тема: цвета, шкала шрифтов, сетки, адаптив
css/texture.css     — бумажная фактура (зерно, рваный край, чернильное пятно)
css/animations.css  — появление при скролле, кроссфейд языка
css/admin.css       — оформление админки

js/content.js       — ВЕСЬ контент сайта (RU + EN). Редактируется админкой
js/flags.js         — включатели необязательных эффектов (см. ниже)
js/common.js        — общая логика: язык, шапка, скролл, плитки медиа, лайтбокс
js/page-*.js        — рендер конкретной страницы
js/reviews.js       — отзывы: карточки, карусель, форма «оставить отзыв»
js/mobile-carousel.js — на телефоне сетки карточек и галереи листаются вбок
js/hero-cinematic.js — анимация первого экрана (работает по флагу)
js/admin.js         — админка

css/hero-cinematic.css — стили анимации первого экрана (работают по флагу)

server/server.js        — локальный сервер (сайт + API админки)
server/content-store.js — чтение и запись js/content.js, резервные копии
server/media.js         — загрузка и сжатие медиа

assets/media/       — фото, видео и аудио, разложенные по разделам:
    home/           — первый экран, ознакомительный ролик, фоны разделов главной
    about/          — портрет и фото для «Обо мне»
    services/       — фото услуг
    portfolio/<id>/ — папка своя у каждого проекта
    blog/<id>/      — папка своя у каждой новости
    reviews/        — фото авторов отзывов
    archive/        — всё, что больше нигде не используется
backups/            — резервные копии контента

privacy.html        — политика конфиденциальности
post.html           — страница отдельной новости (post.html?id=…)
ЮРИДИЧЕСКОЕ.md      — авторские права, персональные данные, чек-лист запуска
```

### Как включить и выключить анимацию первого экрана

В файле `js/flags.js` есть один переключатель:

```js
window.SITE_FLAGS = {
  heroCinematic: true
};
```

`true` — при прокрутке главной фото растворяется, под ним проступают световые
пятна, описание и кнопки сжимаются, надпись «Ознакомительный ролик» с
заголовком подъезжает вверх к имени, а справа от текста всплывает сам ролик.
Отдельного раздела с видео при этом нет — он стал частью первого экрана.

`false` — всё как было раньше: обычный первый экран и отдельный раздел с
заголовком слева и видео справа. Больше ничего менять не нужно — ни стили,
ни разметку.

Режим включается только в широком окне (от 1025 пикселей). В узком окне,
на планшете и телефоне ролик рядом с текстом уже не помещается, поэтому там
всегда работает прежний вариант: первый экран и раздел «Ознакомительный
ролик» — два отдельных раздела со своими фонами. При включённой в системе
экономии движения анимация тоже не применяется.

**Правило:** чтобы поменять текст или картинку, HTML и JS трогать не нужно —
всё лежит в `js/content.js` и правится через админку.

### Папки медиа заводятся сами

Папку под файлы не надо создавать руками. При сохранении в админке сервер
сверяет папки с контентом:

- появился новый проект или новость — появляется и папка
  `portfolio/<идентификатор>` или `blog/<идентификатор>`;
- проект или новость удалили — их папка уезжает в `archive/` с датой в имени.
  Насовсем ничего не стирается: опечатка в идентификаторе не должна стоить
  фотографий. Ненужное из `archive/` удаляйте вручную или через медиатеку;
- когда вы выбираете фото или видео в карточке проекта, окно медиатеки сразу
  открывается в папке этого проекта, и загруженный файл попадает туда же.

## 4. Дизайн

Тёмно-угольная палитра с медным акцентом и лёгкой печатной фактурой.

Все размеры шрифтов и отступов заданы токенами в начале `css/styles.css`
(`--fs-sm`, `--fs-md`, `--sp-section` и т.д.). Если менять типографику —
меняйте токены, а не отдельные компоненты, иначе блоки снова разъедутся.

### На телефоне карточки листаются вбок

При ширине экрана до 760 px сетки карточек и галереи превращаются в карусель:
одна карточка на экран, следующая выглядывает из-за края, под лентой — точки.
Так работают услуги, портфолио, новости, блок «Для кого», цифры проекта,
фото, видео и аудио в кейсе. Список шагов рабочего процесса остаётся
столбиком: там важен порядок сверху вниз.

Всё делает `js/mobile-carousel.js` — он вешает на контейнер класс `.mcar`
и дорисовывает точки; сама раскладка лежит в конце `css/styles.css`
в разделе «МОБИЛЬНАЯ КАРУСЕЛЬ». Чтобы добавить в карусель ещё один блок или
убрать из неё существующий, правьте список `SELECTOR` в начале скрипта;
ширину карточки для каждого типа задаёт `--mcar-item` в стилях.
На широком экране класс снимается и всё возвращается к обычной сетке.

### Живые фоны

Два разных эффекта, оба в `css/texture.css`, разметку создаёт `js/common.js`:

- **Чернильное поле** — в шапках внутренних страниц («Обо мне», «Портфолио»,
  «Услуги», «Новости»). Шесть цветных пятен медленно плывут по своим
  траекториям и перетекают друг в друга. Насыщенность правится через `alpha`
  в `.ink-blob.b1…b6`, скорость — через `animation-duration`. На странице
  проекта поле показывается только если у проекта нет своего фото в шапке.
- **Световые пятна** — в однотонных разделах главной (`data-glow` в
  `index.html`). Намеренно очень слабые: проявляются, когда раздел входит
  в экран, гаснут при выходе и слегка смещаются при прокрутке. Если покажется
  много — уменьшайте `alpha` в `.glow.g1…g3`.

Оба эффекта отключаются системной настройкой «уменьшить движение»
(`prefers-reduced-motion`), а измерения при прокрутке идут через
`requestAnimationFrame`, чтобы не дёргалась страница.

### Фоны разделов главной

У каждого раздела главной есть поле **«Фото в фоне раздела»**. Задали фото —
раздел показывает его приглушённо; оставили пустым — раздел однотонный, а
в фоне работают световые пятна. Переключением занимается `setBgPhoto`
в `js/page-home.js`, вручную в разметке ничего править не нужно.

Фото сдвигаются при прокрутке: слой `.section-photo-bg` выводится крупнее
раздела (`inset: -9% 0`), и этот запас расходуется на параллакс.

Стыки разделов — обычные, встык по цвету: размытые переходы пробовали,
выглядит грязно.

Пара решений, которые стоит сохранить при доработках:

- **Не ставьте фото в двух соседних разделах подряд** — страница становится
  грязной. Чередуйте с однотонными.
- **`.staff-divider`** — разделитель в виде нотного стана с медной нотой.
  Ставится вручную и намеренно редко.
- **Карточки «Для кого»** — не сетка, а поток (`.for-whom-grid`): они сами
  разбираются по рядам и растягиваются поровну при любом количестве.
  Свечение при наведении идёт за курсором (`--mx`/`--my` обновляет
  `setupCardGlow` в `js/common.js`); на тач-устройствах не включается.
- **Пятна раскладываются по-разному** в соседних разделах — классы
  `.glow-field--a…d` и разные фазы анимации, иначе во всех разделах они
  оказываются на одних и тех же местах.

### Видео в проекте

У каждого ролика в портфолио два способа подключения: **файл** (загружается
через админку, сжимается в MP4) или **ссылка на YouTube / VK / Rutube** —
поле «Ссылка на YouTube / VK / Rutube». Если ссылка заполнена, файл не нужен:
вставляется плеер сервиса. Достаточно скопировать адрес из адресной строки —
`embedURL` в `js/common.js` сам приведёт его к нужному виду.
- **Карточки услуг** раскрываются по клику (весь блок кликабельный). Фото
  в фоне лежит отдельным слоем, а затемнение — псевдоэлементом карточки:
  если сделать вуаль внутри слоя с фото, прозрачность гасит и её саму,
  и снимок пропадает. Плотность фото регулируется только вуалью
  (`.service-card.has-photo::after`). Высоту раскрытого текста считает JS —
  вариант на grid-строках `0fr → 1fr` в этой раскладке схлопывался.
- **Сетки карточек** (`.card-grid`) держат рамки на самих карточках, а не на
  фоне-зазоре. Поэтому неполный последний ряд (7 услуг в 3 колонки) выглядит
  нормально, а не как дырки в тёмной сетке.
- **Вертикальные видео не обрезаются.** Плитка подстраивается под пропорции
  кадра (`applyVideoAspects` в `js/common.js`).
- **Фото в галерее проекта** заполняют плитку, но по клику открываются целиком
  в лайтбоксе — так ничего не теряется.
- **Фото, видео и аудио на странице проекта** идут отдельными блоками,
  а не вперемешку.

## 5. Заявки и отзывы — приходят в Telegram

Обе формы сайта (заявка в «Контактах» и «Оставить отзыв») отправляют сообщение
в Telegram и **ничего не сохраняют на сервере**: ни базы, ни файла с адресами.
Так на сайте не копятся чужие персональные данные — меньше и хлопот, и
ответственности по 152-ФЗ.

Работает это через `send.php` — единственный серверный файл сайта. PHP есть на
любом виртуальном хостинге, ничего доустанавливать не нужно.

### Разовая настройка

1. Откройте бота в Telegram и нажмите «Запустить» (`/start`).
2. Выполните в папке сайта:

```bash
node server/telegram-setup.js
```

Скрипт узнает ваш `chat_id` и впишет его в `send.php`. Проверить связь:

```bash
node server/telegram-setup.js --test
```

Токен бота лежит в `send.php`. Файл исполняется сервером, посетителю его
содержимое не отдаётся, но пересылать его кому-либо нельзя. Если токен утёк —
отзовите в @BotFather (`/revoke`) и впишите новый.

### Отзыв с сайта

Отзыв приходит вам в Telegram. Чтобы он появился на сайте, добавьте его в
админке: раздел «Отзывы» → «Добавить отзыв». Так вы всегда видите текст до
публикации, а на сервере ничего не хранится.

## 6. Публикация сайта

На хостинг заливаются статика и `send.php`:

```
*.html (кроме admin.html), send.php, favicon.svg,
css/ (кроме admin.css), js/ (кроме admin.js), assets/
```

Не заливайте: `admin.html`, `js/admin.js`, `css/admin.css`, `server/`,
`backups/`, `package.json`, `start.command`, `*.md`.

Хостинг подойдёт любой с поддержкой PHP — например, виртуальный хостинг
reg.ru. Домен покупается там же и привязывается по инструкции хостинга.
Обязательно включите бесплатный SSL-сертификат (Let's Encrypt) — без него
браузеры показывают «Не защищено».

### Как обновлять сайт после правок

Админка живёт на вашем компьютере, хостинг отдаёт готовую статику. После
правок в админке залейте по FTP два места:

- `js/content.js` — весь текст сайта;
- `assets/media/` — если добавляли фото, видео или аудио.

Остальные файлы меняются, только когда правится сам код сайта.

### Если захотите админку онлайн

`server/server.js` для этого уже готов: он и отдаёт сайт, и обслуживает API.
Нужен хостинг с Node.js (VPS, Timeweb Cloud, Render и т.п.), а при запуске
задать переменные:

```bash
HOST=0.0.0.0 PORT=8080 ADMIN_PASSWORD="длинный-пароль" node server/server.js
```

После этого контент можно править с любого устройства, а загруженные файлы
будут сразу попадать на сайт — без перезаливки папки. Обязательно поставьте
сложный пароль и HTTPS (обычно даётся хостингом или через Caddy/nginx).
